[02:00] Agent Stack Release Readout: Hermes Agent v0.23.0

Hermes Agent ने 5 नवंबर, 2026 को v0.23.0 जारी किया। यह उन लोगों के लिए एक व्यावहारिक बदलाव है जो कई सतहों पर agents चलाते हैं: अब पूरा Desktop workspace ब्राउज़र tab में खोला जा सकता है। नया Webapp आपके अपने gateway से वही chats, Group Chats, plugins और settings उपलब्ध कराता है। इसे आपके नेटवर्क में ब्राउज़र के माध्यम से या sign-in के साथ public URL से एक्सेस किया जा सकता है। Webapp Docker image और Nix package, दोनों के साथ शामिल है। Access डिफ़ॉल्ट रूप से बंद रहता है और इसे webapp.enabled या Settings में Web Access के ज़रिए सक्षम किया जा सकता है।

इस release ने Hermes Agent के काम को समन्वित करने का तरीका भी बदला है। अब हर machine पर एक gateway चलता है, जो उसके sessions का स्वामित्व संभालता है, जबकि CLI, terminal interface, Desktop, editors, messaging bots और cron उसी gateway के clients के रूप में जुड़ते हैं। इससे विभिन्न सतहें एक ही conversations तक पहुँच सकती हैं, बिना यह कि हर एक अपना अलग agent चलाए। इससे duplicate-message और missing-message की समस्याएँ कम हो जाती हैं, जो पहले कई interfaces के स्वतंत्र रूप से काम करने पर हो सकती थीं। Desktop एक बार में कई machines को जुड़े रख सकता है, जबकि Group Chats अपनी conversations स्वयं route करते हैं।

इसी आधार पर, v0.23.0 में self-updating plugins, paid MCP tools के लिए price tags और spending limits, और pluggable delegation जोड़े गए हैं। Plugin catalog लगभग 600 entries से बढ़कर 1,050 से अधिक entries तक पहुँच गया है, और built-in skill set अधिक सहज हो गया है। Release में memory और latency पर काम भी शामिल है, जिसका उद्देश्य long-lived gateways को बेहतर बनाना है।

[02:44] OpenAI ने Linux kernel के लिए 948 सत्यापित सुरक्षा patches तैयार किए

OpenAI ने एक स्वायत्त pipeline बनाई, जिसने Linux kernel में local privilege-escalation vulnerabilities की खोज, सत्यापन और 948 patches तैयार किए। Local privilege-escalation vulnerability एक ऐसी कमी है जो सीमित पहुँच रखने वाले किसी व्यक्ति को उसी machine पर अधिक privileges प्राप्त करने देती है। इसलिए ऐसी समस्याएँ सामान्य पहुँच को बहुत अधिक नियंत्रण में बदल सकती हैं।

महत्वपूर्ण बदलाव यह नहीं है कि AI ने केवल code तैयार किया। इस system ने काम को तीन जुड़े हुए चरणों—discovery, validation और patch generation—के माध्यम से पूरा किया। Linux kernel पर लागू होने पर—यह hardware और अन्य system resources का प्रबंधन करने वाला core system software है—इस दृष्टिकोण ने अलग-अलग vulnerabilities के लिए 948 patch candidates तैयार किए।

मेंटेनर्स के लिए, यह परिणाम सुरक्षा कार्य को स्वचालित बनाने के बजाय ठीक-ठाक्क सुधारों की एक बड़ी मात्रा प्रस्तुत करता है। यह बिल्डर्स को भेद्यता-उपचार प्रणालियों के लिए एक ठोस मॉडल भी देता है, जो किसी कमी को खोजने से लेकर उसकी जाँच करने और मरम्मत तैयार करने तक आगे बढ़ती है।

आगे क्या देखना है, यह है कि इनमें से कितने पैच मेंटेनर समीक्षा में बने रहते हैं और Linux kernel का हिस्सा बनते हैं। पाइपलाइन ने अपना बताया गया खोज-और-पैच-निर्माण चक्र पूरा कर लिया है; अपस्ट्रीम में स्वीकृति अगला महत्वपूर्ण परीक्षण है।
